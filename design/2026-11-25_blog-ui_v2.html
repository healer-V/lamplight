    上一篇用 Express 写出了增删查接口，但数据存放在内存数组里，服务一重启就丢失。这一篇把数据存进 SQLite 数据库，学习够用的 SQL，再写一个调用这些接口的前端页面，从空目录开始完成一个能真正使用的待办清单应用。

    一、为什么需要数据库

    1. 内存、文件和数据库

    保存数据大致有三种做法：

    做法问题或优势
    存在内存变量里进程退出即丢失，也无法在多台服务器之间共享
    自己写 JSON 文件能持久保存，但每次修改都要读出整个文件再写回；两个请求同时写入时可能互相覆盖，查询和筛选都要自己实现
    存进数据库数据持久保存；支持按条件查询、排序和并发读写；保证写入要么完整成功、要么完全不生效

    2. 为什么入门选 SQLite

    MySQL 和 PostgreSQL 需要单独安装并启动数据库服务。SQLite 不需要服务进程，整个数据库就是磁盘上的一个文件，程序直接读写这个文件即可。

    关于实验性提示node:sqlite 在 Node.js 22 中仍标记为实验性功能，运行时会输出一行 ExperimentalWarning，不影响本文的使用。

    二、创建项目

    1. 初始化

    终端
    mkdir todo-app
cd todo-app
npm init -y
npm pkg set type=module
npm install express@5

    2. 最终的目录结构

    后端分成 db.js 和 server.js 两个文件：db.js 只负责和数据库打交道，server.js 只负责处理 HTTP 请求。

    三、先学会够用的 SQL

    1. 表结构与增删改查

    sql-demo.js
    import { DatabaseSync } from 'node:sqlite'

const db = new DatabaseSync(':memory:')

db.exec(`
  CREATE TABLE todos (
    id    INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT    NOT NULL,
    done  INTEGER NOT NULL DEFAULT 0
  )
`)

    2. 用占位符防止 SQL 注入

    注意 SQL 里的 ?：它是占位符，真正的值通过 run(值)、get(值) 单独传入。千万不要用字符串拼接 SQL。

    3. prepare、run、get、all 的区别

    db.prepare(sql) 把 SQL 预编译成一条语句对象，然后按用途调用 run、get 或 all。

    四、编写后端

    1. 数据层 db.js

    文件不存在时会自动创建，这就是数据能跨重启保存的原因。

    2. 接口层 server.js

    页面和接口来自同一个源，前端调用接口时不存在跨域问题。

    五、编写前端页面

    1. 页面结构 index.html

    页面只有一个输入框、一个按钮和一个列表。

    2. 交互逻辑 app.js

    待办标题用 textContent 而不是 innerHTML 写入页面，防止 XSS 攻击。
